# ADR 0003 — WebAssembly kernels: `no_std` Rust, zero imports, a bump arena and ABI v1

- **Status:** Accepted
- **Date:** 2026-10-13
- **Scope:** `wasm/**`, `scripts/build-wasm.mjs`, `src/lib/wasm/**`, `src/wasm/`, `tests/unit/wasm/**`

## Context

The site makes theorems tangible through interactive labs: the Fourier series and the Gibbs phenomenon,
Nyquist–Shannon sampling and aliasing, Shannon's source-coding theorem (entropy and Huffman codes), chaos in the
logistic map, the central limit theorem, and a subtle generative hero animation. These need tight numeric loops
(FFTs, millions of map iterations, particle advection) that should run at frame rate on modest phones, and they
must give the same answers as the mathematics stated beside them.

The site also has to stay light (docs/arquitetura.md §2.7): static HTML, no UI framework, every behaviour loaded
on demand, a Content Security Policy that only adds `'wasm-unsafe-eval'` for scripts. The usual Rust-to-Web
toolchain (`wasm-bindgen`/`wasm-pack`) generates JavaScript glue, imports and a heap allocator; that is more
code and more surface than a handful of numeric kernels need.

Forces:

- **Size.** Each module is downloaded only on pages that use it, but it should still cost a few kilobytes,
  not tens (hard budget 48 KiB raw per module, also enforced on `dist/` by `scripts/check-budgets.ts`).
- **Determinism and testability.** Kernels must be checkable against independent references, both as Rust host
  tests and through the real `.wasm` bytes from Node, with no browser.
- **Robustness.** Labs feed kernels user-controlled values (sliders, text). A trap or an out-of-bounds write in
  linear memory must be impossible, whatever the arguments.
- **Memory growth.** `memory.grow` detaches every `ArrayBuffer` view of the old memory; an API that lets callers
  keep views silently breaks.

## Decision

### 1. Toolchain and layout

- A Cargo workspace at `wasm/` (`resolver = "3"`, edition 2024), pinned by `wasm/rust-toolchain.toml` to Rust
  **1.97.0** with the `wasm32-unknown-unknown` target, `rustfmt` and `clippy` (profile `minimal`).
- Crates: `kernel-core` (`rlib`: ABI, arena, validated memory views) and three `cdylib`s whose `[lib] name`
  yields `signal.wasm`, `information.wasm` and `dynamics.wasm`. Mathematics lives in plain, host-testable
  functions (`fft.rs`, `huffman.rs`, `noise.rs`, …); the `extern "C"` exports in each `lib.rs` are thin wrappers
  that validate arguments and call them.
- `#![cfg_attr(not(test), no_std)]` everywhere. Outside tests a `#[panic_handler]` (generated by
  `kernel_core::export_abi!`) executes `core::arch::wasm32::unreachable()`: no panic or formatting machinery is
  linked, so **every module has zero imports**. The only dependency is `libm = "0.2"` (pure-Rust math). No
  `wasm-bindgen`, `wasm-pack`, allocator crate or `std` on the wasm target.
- Rust 2024 rules for statics: global state lives in `UnsafeCell` wrappers with `unsafe impl Sync` (the modules
  are single-threaded: no threads, no shared memory); there are no references to `static mut`.
- Release profile: `lto = true`, `codegen-units = 1`, `panic = "abort"`, `strip = true`, `debug = false`,
  `opt-level = "s"` (measured, see §6). `wasm/.cargo/config.toml` links with `-zstack-size=65536`: the kernels
  never recurse and keep large scratch buffers in the arena, so a 64 KiB shadow stack replaces the 1 MiB default
  and the initial memory is 2 pages (128 KiB).
- Quality gates: `cargo fmt --check`, `cargo clippy --all-targets -D warnings` (host) and
  `cargo clippy --target wasm32-unknown-unknown -D warnings`, `cargo test --workspace`; workspace lints deny
  `unsafe_op_in_unsafe_fn` and warn on `missing_docs`, `unreachable_pub` and undocumented `unsafe` blocks.

### 2. Memory model

```text
0 ── shadow stack (64 KiB) ── static data ── __heap_base ── persistent ── floor ── transient ── top ── free
```

- **Bump arena** from the linker symbol `__heap_base` (rounded up to 16). `arena_alloc(bytes, align)` returns an
  aligned offset, growing memory with `memory.grow` when needed, or `0` on failure (alignment not a power of two,
  memory cannot grow, region would cross 4 GiB). `arena_reset()` rewinds `top` to `floor`; `arena_used()` reports
  `top − base`.
- **Persistent blocks.** A kernel may _pin_ state so that `arena_reset` keeps it. Only the flow field does:
  `flow_init` releases the **whole** arena, allocates its particle and segment buffers and pins them.
- **Validated views.** A caller pointer `(ptr, len)` of `T` is accepted only if it is non-null, aligned to
  `T`, lies entirely in the live transient range `[floor, top)` and spans at most `isize::MAX` bytes; an output
  must not overlap any input (except where documented: `multiply` may write in place). Violations return `−4`
  (or `NaN`/`0` for functions without a status code). Zero-length regions are always valid and never
  dereferenced. So a bad argument can never corrupt the stack, static data or pinned state, nor trap.
- **Scratch space** (`arena::Temp`) is bump-allocated above every caller region after validation and rewound
  before the call returns (Huffman queues, the 256×256 bigram table, Fourier coefficients, column sums).
- No kernel traps: integer division by user values does not occur, float→int casts saturate, indices are
  bounded, and the release build contains no reachable panic. `tests/unit/wasm/modules.test.ts` fuzzes every
  export with hostile integers, NaN/±∞, misaligned and out-of-arena pointers and random memory contents.

### 3. ABI version 1

All pointers and sizes are `u32` (byte offsets); floats are `f64` except rendering buffers (`f32`, noted).
Every module exports `memory` and exactly the functions below (the linker's `__heap_base`/`__data_end` are not
exported; `scripts/build-wasm.mjs` and the tests check the exact list).

| Status code (`i32`) | Meaning                                                                               |
| ------------------: | ------------------------------------------------------------------------------------- |
|                 `0` | OK (functions that return a count return `≥ 0`)                                       |
|                `−1` | invalid length (zero where meaningless, or above a documented limit)                  |
|                `−2` | length is not a power of two                                                          |
|                `−3` | out of memory (scratch or state could not be allocated)                               |
|                `−4` | invalid parameter (non-finite, out of range, or a pointer that fails §2's validation) |

### 4. Numerical choices worth knowing

- **FFT** twiddles are evaluated directly with `sincos` (N − 1 calls) rather than by recurrence: error stays
  `O(ε log N)` (max error against a naive DFT < 1e−9·N for N = 1024).
- **Fourier partial sums** advance `sin(kx)` with the Chebyshev recurrence and re-seed exact values every 32
  terms; the phase is reduced modulo 2π first.
- **Sinc reconstruction** uses `sin(π(v − k)) = (−1)^{k+r} sin(π(v − r))`, `r = round(v)`: one `sin` per output
  point, exact at sample instants.
- **Huffman** sorts leaves with an in-place heapsort (keys `count·2^32 + index` are unique) and merges with two
  queues: `O(k log k)`, no allocation besides arena scratch.
- **Simplex noise** follows Gustavson's reference with two documented changes: kernel radius `r² = 0.5` instead of
  `0.6` (with `0.6` a vertex outside the simplex can lie inside its kernel but is never summed, so the field jumps
  by up to ~5·10⁻³ across simplex faces; with `0.5` it is continuous), and normalisation by the exact worst-case
  amplitude `0.013007157182859354` (numerical maximisation, re-verified by an independent search), so the output
  spans `[−1, 1]` and is clamped only against rounding. Seeding hashes the seed with `lowbias32` and XORs its bytes
  into Perlin's permutation lookups; seed `0` is exactly the reference hash.
- **Flow particles** are `f32 [x, y, age, life]`; lifetimes are uniform in `[2, 6)` time units, `alpha` fades in
  and out over the first and last 20 % of each life, and a respawn emits a degenerate segment with `alpha = 0`.
- **Logistic map** iterates are clamped to `[0, 1]` against rounding; the bifurcation image and the Lyapunov
  curve start from the critical point `x = ½`, which every stable cycle attracts (Singer 1978).

### 5. TypeScript layer (`src/lib/wasm/`)

- `runtime.ts`: `instantiateFromBytes(bytes)` and `instantiateFromUrl(url)` (`instantiateStreaming` when the
  response is `application/wasm`, otherwise `arrayBuffer()`; one promise per URL, evicted on failure); both check
  `abi_version() === 1`. `withArena(kernel, fn)` hands `fn` an `Arena` whose `ArenaBuffer`s never cache views:
  `view()` builds a fresh typed array over the current `memory.buffer` (valid until the next kernel call) and
  `read()` copies out; buffers refuse access after their scope, nested scopes share one reset, and async callbacks
  are rejected. `KernelError` carries the status code; `inArenaScope` guards whole-arena operations.
- `signal.ts`, `information.ts`, `dynamics.ts`: each exports the raw-exports interface, the ergonomic kernel
  interface, a pure `createXKernel(exports)` (copies `Float64Array`/`Uint32Array`/`Float32Array` in and out;
  invalid arguments throw `RangeError`, kernel failures `KernelError`) and `loadX()`, which dynamically imports
  `load-x.ts`. Only these tiny entry files contain `import url from '../../wasm/x.wasm?url'`, so the Node tests
  never touch `?url`, and a page fetches a module only when one of its islands calls `loadX()`.
  `wasm-url.d.ts` types `*.wasm?url` independently of `vite/client`.
- `vite.build.assetsInlineLimit = 0` (astro.config.ts) keeps every module a hashed file in `/_astro/` (all three
  are above Vite's default 4 KiB inlining threshold anyway).

### 6. Build pipeline and the opt-level measurement

`node scripts/build-wasm.mjs` (plain Node ESM, no dependencies; `--check` validates without writing):
`cargo build --release --locked --target wasm32-unknown-unknown` in `wasm/` → strip custom sections (`producers`,
`target_features`) → `wasm-opt -Oz` with the six features rustc enables by default, **only** if a `wasm-opt`
binary is on `PATH` and only if it shrinks the module → validation with `WebAssembly.compile` (zero imports,
exact export list, `abi_version() === 1`, arena smoke test) → budget (warn > 24 KiB, fail > 48 KiB raw) →
table of raw and gzip sizes → `src/wasm/{signal,information,dynamics}.wasm` and `src/wasm/manifest.json`, a JSON
array of `{ name, bytes, gzipBytes, sha256 }` (`bytes` raw; gzip at zlib's default level 6, as
`scripts/check-budgets.ts` measures). Outputs are git-ignored; `pnpm build`/`pnpm dev` run the script first.

**Chosen: `opt-level = "s"` for the whole workspace.** It is the smallest on the wire (−10 % gzip vs `3`, −4 % vs
`"z"`), the smallest raw in total, and as fast as `3` on the frame-critical paths (FFT, flow field, bifurcation,
CLT); it is at most ~1.7× slower on sub-5 ms one-shot computations. `"z"` saves nothing on the wire and is up to
2.3× slower. Re-measure when the toolchain or the kernels change.

## Consequences

Positive:

- Three modules of ≈ 10–16 KiB raw (4–8 KiB gzip), zero imports, no JavaScript glue; each page downloads only the
  module its labs use, after an island asks for it. CSP needs nothing beyond `'wasm-unsafe-eval'`.
- One contract for every kernel: status codes, `NaN` conventions and documented degenerate cases; hostile input
  cannot trap or corrupt memory (fuzzed by the test suite).
- Correctness is checked three ways: Rust host tests of the plain functions; Vitest suites that run the built
  bytes against independent JavaScript references — several bit for bit (Lorenz RK4, PCG32/CLT histograms, the
  bifurcation image, simplex noise, the curl-noise step) — and against analytic results (Parseval, Gibbs constant,
  `λ(4) = ln 2`, CLRS's Huffman example, `C_BSC(0.11) ≈ ½`, …); and module-level checks (imports, exact exports,
  manifest integrity, size budget).

Negative and trade-offs:

- Hand-written ABI: adding a kernel means touching the Rust export, the TypeScript interfaces, the export lists in
  `build-wasm.mjs` and `modules.test.ts`, and this ADR. The exact-export checks make forgetting one a build error.
- Pointers must come from `arena_alloc` since the last reset; callers cannot pass views of other memory. Callers
  using the raw exports must re-create typed-array views after any call that may grow memory (the wrappers do).
- One flow field per module instance; `flow_init` invalidates every arena allocation (the TypeScript wrapper
  refuses to call it inside `withArena`). Two hero animations on one page would have to share it.
- `wasm-opt` is optional: builds without Binaryen are reproducible but a few percent larger.

Deviations from the original specification, with reasons:

- **Lanczos σ-factors and "overshoot below 1.02".** With the specified factors `sinc(k/(M+1))` the peak of the
  σ-smoothed square wave converges to ≈ 1.02374 (measured 1.023497, 1.023730, 1.023738 for H = 10, 50, 200),
  i.e. 1.19 % of the jump instead of 8.95 %. The bound "< 1.02" cannot be met by that definition, so the tests
  assert the attainable facts: peak < 1.025, within 2·10⁻³ of 1.02374, and a ≥ 7× smaller overshoot.
- **Simplex noise kernel radius** `r² = 0.5` (not Gustavson's `0.6`) and exact normalisation, for continuity and
  a true `[−1, 1]` range (§4).
- **`arena_reset` keeps pinned state.** It frees every transient allocation but not the flow field pinned by
  `flow_init`; otherwise any scoped computation on `dynamics.wasm` (every wrapper call resets the arena) would
  destroy the hero animation's particles. `flow_init` itself releases everything.
- **`clt_histogram` seed** is passed as two `u32` halves (`seed_lo`, `seed_hi`): JavaScript cannot pass an `i64`
  without `BigInt` glue, and the halves keep the ABI uniform. `DynamicsKernel.cltHistogram` accepts a number or a
  `bigint`.
- **Stricter validation than stated:** pointers outside the live arena, misaligned or overlapping outputs are
  rejected (`−4`/`NaN`/`0`); the logistic kernels require `r ∈ [0, 4]`, `x0 ∈ [0, 1]` (the orbit then stays in
  `[0, 1]`); `logistic_lyapunov` returns `NaN` for `n = 0`; `huffman_lengths` returns `NaN` for `k > 4096`.
- **`magnitude`/`power_db`** compute `hypot(re, im)` (and `20·log10(|X|/n)`), the same quantities without
  overflow or underflow of `|X|²`.
- **Location.** docs/arquitetura.md §3 lists the loaders under `src/adapters/wasm/`; this workstream's spec places
  them in `src/lib/wasm/`. The tree in arquitetura.md should be updated (or the folder moved) when merging.
